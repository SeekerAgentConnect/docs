## Connections \{#connections}

| The app says | What it means | What to do |
| --- | --- | --- |
| **Couldn't reach the server** | The server is not running or not reachable from the phone | Start it, or check the address. Over USB, run `adb reverse` again |
| **No live updates** | The server answers but does not stream. Not an outage | Refresh by hand. The server's operator can turn live updates on |
| **Feed offline** | The gateway answers, but the publisher's own server stopped checking in | What was published is still readable. Nothing new arrives until it is back |
| **Disconnected · pair again to reconnect** | The server ended the pairing | Get a new link and pair again, then remove the old connection |
| The pairing link is damaged | The link was shortened or changed before you opened it | Open the whole link, or paste the whole `seekervault://pair` line |
| The server refused the code | The code was already used, expired, or a newer one replaced it | Ask for a new link |
| The certificate isn't trusted | The server has no valid HTTPS certificate for that host name | The operator needs a publicly trusted certificate. Self-signed ones do not work |
| This feed is on another gateway | SAC reads feeds only from the gateway it was built for | Ask the publisher for a link on the SAC gateway |
| This feed is on a gateway this app no longer trusts | The feed was added from another gateway. It stays readable, and nothing from it can be executed | Remove it, and add the feed again from this app's gateway |

## Wallets \{#wallets}

Each direct server signs with the one wallet you chose for it. Its page shows that wallet and whether it can sign; every status is explained on [Connect a server or add a feed](/docs/connecting-servers#wallet-status). A feed signal uses the wallet chosen in its review ([Wallets for feed signals](/docs/wallet-setup#feed-signals)).

| The app says | What it means | What to do |
| --- | --- | --- |
| This connection has no wallet ready to sign | The connection has no wallet, its wallet was removed or needs reconnecting, or the server has not confirmed it | Open the connection and check its **Wallet** row |
| This server hasn't declared which Solana networks it supports | The server is older than this app. SAC does not guess a network, so nothing from it is signed | Ask the server's operator to update it and declare its networks. Its requests stay readable |
| This server no longer supports *network* | The server dropped the network your chosen wallet is on | Choose a wallet on a network it names. SAC never moves the connection for you |
| That wallet's network isn't one this server supports. | You picked a wallet the server cannot use | Pick a wallet on one of the networks the picker names, or **Add wallet for** that network |
| This feed's wallet changed since this review was prepared | The wallet chosen for this feed on the signal's network changed while the review was open. Nothing was signed | Prepare it again for the new wallet |
| The wallet no longer accepts this profile's authorization | The wallet app ended SAC's authorization for that account | **Reconnect** the wallet on the **Wallets** screen |

## Restricted feeds \{#restricted-feeds}

| The app says | What to do |
| --- | --- |
| Waiting for the publisher to approve this device. | Wait with SAC open, or open the feed or tap **Refresh** later |
| The publisher didn't approve this device. | Tap **Send access request** to ask again, or ask the publisher |
| The publisher revoked this device's access to the feed. | Signals you already have stay. Ask the publisher; to ask again, remove the feed and add it again |
| This device's access to the feed has run out. | Tap **Refresh**. If it stays, ask the publisher |

Every access state and message is explained on [Join a Restricted feed](/docs/join-restricted-feed#access-states).

## Reviews and results \{#reviews}

| The app says | What it means | What to do |
| --- | --- | --- |
| No Approve button | The phone could not read the transaction, or it does not match the request | Nothing can be approved from it. Reject it, and tell the sender |
| **Approve and sign** did not open the wallet | The connection's wallet is not ready, or it is on another network than the request names | Open the connection and check its **Wallet** row. A request for another address or network is never signed with a different wallet |
| The quote and the transaction have expired | A prepared swap or order is good for about a minute | Prepare again for a fresh quote |
| **Outcome unknown** | The wallet never reported what it did | Check the wallet's history or an explorer. Never retry from SAC |
| This signal doesn't say which Solana network it is for | The publisher sent it without a network, for example before networks were required. Nothing can be executed from it | Ask the publisher to withdraw it and publish it again with a network |
| This app's gateway couldn't be reached for its network and fee settings | SAC has no recent network and fee settings from its gateway, so nothing was prepared | Try again when you're online |
| The service fee configured for this app changed after this was prepared | The gateway's fee settings changed during the review. Nothing was signed | Prepare it again and review the new terms |
| Staking says the cooldown has not finished, or withdraw first | Read from the chain, not from the request | Wait, or withdraw first, then ask again |

<details>
<summary>Less common messages</summary>

| The app says | What to do |
| --- | --- |
| A signal has no Approve button and says this build or wallet cannot serve it | The feed needs an action this app build does not carry, or a wallet on the signal's network. Update the app, or choose a wallet on that network in the signal's review. Nothing is picked for you |
| This feed reference asks for an access policy this version of the app doesn't know | Update the app, or ask the publisher for a current link |
| The publisher changed these terms | The publisher updated the signal while it was open. Read the new terms and prepare again |
| Your rules changed while this was open | The review was made again. Read it and approve again if you still mean to |
| The history couldn't be read from this phone just now | What is shown is what SAC last read; nothing was changed or removed. Reopen the tab |

</details>

## No notifications \{#notifications}

Allow notifications for SAC in Android **Settings**, and check that the sender supports push. See [Notifications and live updates](/docs/notifications).
