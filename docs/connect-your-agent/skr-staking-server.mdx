The SKR Staking MCP server manages one owner's SKR staking position. Your agent asks to stake, unstake, cancel an unstake or withdraw; the server builds an unsigned transaction from the chain; you review it in SAC and confirm in the wallet. The server never signs.

It is a second, independent server. It has its own pairing, its own token and its own database, and runs side by side with the [general SAC MCP server](/docs/mcp-quickstart) without sharing anything. Pairing it does not touch the general server's pairing.

:::warning[Mainnet only]
SKR staking exists on Solana **mainnet-beta** only. The server checks at startup that its RPC endpoint serves mainnet-beta and refuses otherwise, and it answers only for a phone that chose a **Mainnet** wallet for this server. There is no devnet mode. Its manifest declares Mainnet as its only network, so SAC offers only your Mainnet wallets when you pair it, and there is no network setting to change.
:::

## Prerequisites \{#prerequisites}

- **Node 24.21 or newer**, or Docker.
- A **mainnet RPC endpoint** for `SKR_STAKING_RPC_URL`.
- **SAC on an Android phone** with a **Mainnet** wallet saved ([Connect your wallets](/docs/wallet-setup)). You choose it for this server right after pairing.
- An **MCP client** that speaks Streamable HTTP.

You do not need to stake anything to finish this guide: the first request is a read.

## Step 1: Run the server \{#run-the-server}

Generate a token for your agent with `openssl rand -hex 32` and put it in `SKR_STAKING_MCP_TOKEN`.

<Tabs groupId="mcp-install">
<TabItem value="npm" label="npm package" default>

The server is published on npm as `@seekeragentconnect/mcp-skr-staking`, with the command `seeker-skr-staking-mcp`. Its variables all start with `SKR_STAKING_` and share nothing with the general server:

```sh
mkdir -p ~/.seeker-skr-staking
cat > ~/.seeker-skr-staking/config.env <<'ENV'
SKR_STAKING_DATA_DIR=/home/you/.seeker-skr-staking
SKR_STAKING_HOST=127.0.0.1
SKR_STAKING_PORT=8090
SKR_STAKING_PUBLIC_URL=http://127.0.0.1:8090
SKR_STAKING_MCP_TOKEN=replace-with-a-random-token
SKR_STAKING_RPC_URL=https://replace-with-your-mainnet-rpc
ENV
chmod 600 ~/.seeker-skr-staking/config.env

npx --package=@seekeragentconnect/mcp-skr-staking -- \
  seeker-skr-staking-mcp --config ~/.seeker-skr-staking/config.env start
```

`seeker-skr-staking-mcp --help` lists the commands; `servers/mcp-skr-staking/.env.example` in the source repository lists every variable. `npx` takes the newest release; `--package=@seekeragentconnect/mcp-skr-staking@0.0.1` pins one.

</TabItem>
<TabItem value="docker" label="Docker">

The image `ghcr.io/seekeragentconnect/mcp-skr-staking` is public and listens on 8090, with its SQLite database in `/data`:

```sh
docker run -d --name seeker-skr-staking \
  -p 127.0.0.1:8090:8090 \
  -v seeker-skr-staking-data:/data \
  -e SKR_STAKING_PUBLIC_URL=http://127.0.0.1:8090 \
  -e SKR_STAKING_MCP_TOKEN=replace-with-a-random-token \
  -e SKR_STAKING_RPC_URL=https://replace-with-your-mainnet-rpc \
  ghcr.io/seekeragentconnect/mcp-skr-staking:0.0.1
```

The named volume keeps the pairing and every request across restarts. Pin a version tag as above, or the image digest from the release notes on the source repository's [Releases](https://github.com/SeekerAgentConnect/sac/releases) page.

**Expected result:** the server keeps running and listens on port 8090. A server whose RPC endpoint is not mainnet-beta stops at startup instead.

## Step 2: Connect your agent \{#connect-your-agent}

Point your agent at `http://127.0.0.1:8090/mcp` with `Authorization: Bearer <SKR_STAKING_MCP_TOKEN>`. For a client that takes an `mcpServers` JSON file:

```json
{
  "mcpServers": {
    "skr-staking": {
      "type": "http",
      "url": "http://127.0.0.1:8090/mcp",
      "headers": { "Authorization": "Bearer ${SKR_STAKING_MCP_TOKEN}" }
    }
  }
}
```

Other clients: [Connect your agent](/docs/connect-your-agent).

## Step 3: Pair your phone \{#pair-your-phone}

Ask the agent to connect your phone. It calls `skr_create_pairing_link`; open the link on the phone and tap **Pair**. From a shell on the host, the server's `pair` command prints the same code: `seeker-skr-staking-mcp --config … pair` (npm), `docker exec seeker-skr-staking node servers/mcp-skr-staking/dist/cli.js pair` (Docker), or `node --env-file-if-exists=.env servers/mcp-skr-staking/src/cli.ts pair` in a checkout. Everything else, including reaching a server on your computer from the phone, is on [Pair your phone and enable push](/docs/pair-your-phone).

**Expected result:** SAC lists the SKR staking server as its own connection, next to any other server you paired, and opens its wallet picker with your Mainnet wallets. Choose the account that holds your SKR and tap **Use this wallet**. Other connections keep their own wallets.

## Step 4: Read your position \{#read-your-position}

Ask the agent to call `get_staking_status`. It creates no request, asks you nothing and builds no transaction. It answers with your available, staked and unstaking SKR, whether a cooldown has finished, the program's minimum stake, and a `display` sentence.

**Expected result:** the agent can tell you your position. If it says there is no connected wallet, pair the phone, or choose a Mainnet wallet on this server's page in SAC.

## Step 5: Follow a staking request \{#staking-request}

When you decide to act, the agent calls one of:

| Tool | Asks you to | Takes |
| --- | --- | --- |
| `request_stake` | Stake `amount` SKR | `amount`, `idempotency_key` |
| `request_unstake` | Start unstaking `amount`. Starts the cooldown; moves nothing yet | `amount`, `idempotency_key` |
| `request_cancel_unstake` | Put the whole pending unstake back to work | `idempotency_key` |
| `request_withdraw` | Withdraw what a finished cooldown released | `idempotency_key` |

`amount` is SKR base units as a string; SKR has six decimals, so 1 SKR is `"1000000"`. The wallet is never a parameter: it is the one you chose for this server in SAC. Each tool also takes an optional `note`, shown apart from the verified details, and `expires_in_seconds`.

On the phone each operation has its own review and button. SAC checks the transaction against the staking program before the wallet opens; then you confirm in Seed Vault Wallet.

**Reading the result.** There is no separate get or cancel tool. To follow a request, the agent calls **the same tool again with the same `idempotency_key` and parameters**; it gets the original request as it stands now. `CONFIRMED` carries the transaction `signature`; `UNKNOWN` means nobody knows whether it was sent, and it must never be retried. A request cannot be cancelled by the agent; you reject it on the phone, or it expires.

## Step 6: Enable push (optional) \{#enable-push}

This server wakes the phone only through the SAC relay: set `SKR_STAKING_RELAY_URL`, `SKR_STAKING_RELAY_SERVER_ID` and `SKR_STAKING_RELAY_CREDENTIAL`. See [Enable push wake-ups](/docs/pair-your-phone#enable-push).

## Troubleshooting \{#troubleshooting}

| The agent reads | What to do |
| --- | --- |
| No connected wallet | Pair the phone, or choose a wallet on this server's page in SAC |
| `INVALID_PARAMETERS` on a devnet or testnet wallet | Choose a **Mainnet** wallet for this server; it serves nothing else. Only a phone older than network declarations can bind another network |
| `CHAIN_UNAVAILABLE` | The RPC endpoint did not answer. Try again |
| Below the minimum stake, insufficient balance | Checked on chain before you are asked. Adjust the amount |
| Nothing staked, nothing pending, cooldown not finished | Read `get_staking_status`; withdraw first, or wait |
